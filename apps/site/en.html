APPEND-ONLY EVENT LOG

The five-element event store is append-only; 100% logging coverage is a runtime invariant. Every operation is replayable, attributable, and reversible via compensating events — no fake victory broadcasts.

🛑 The emergency brake hangs in the most visible spot on the bridge, always

Running a business is not a game save — there is no reload. So this system's safety design outweighs any game's. One tap on any end pauses every agent, fleet-wide in ≤60 seconds (including safe abortion of browser actions). A product-level safety commitment, not decoration.

Never execute when uncertainUncertain items at night only write "escalation" events — guessing is forbidden. An escalation ▲ is not failure; it is the squad calling the captain.
No receipt, no claimKey numbers must come from tool receipts; anything unreceipted is explicitly marked "unverified" — never glossed over.
Errors are reversibleRollback = a compensating event sequence in reverse. The original flight log is never modified, but the course can always be corrected.

NEW SPECIES · AI-NATIVE AGENT IM

The first-class citizen is not the message — it's the accountable action

Traditional IM digitized communication, but never digitized action — a message goes out, and a human still has to go do the thing. Agent IM is an AI-native collaboration foundation: every action has an actor, an authorization, a result, and a tamper-proof trace.

The clearest dividing line is the approval card: in Feishu (Lark), an approval card is a bolted-on OA plugin — one tap kicks you out of IM into another system. In HyperReality, the approval card is a native message type; the approval gesture writes straight back into the event store as a calibration sample. That difference is the difference between two eras. The served subject has changed too: traditional IM serves humans; Agent IM serves AI — the subject has switched.
