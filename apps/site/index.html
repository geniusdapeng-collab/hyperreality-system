DOWNLOAD · 首航检查单

三步启航，和装一个 Mac 软件一样简单

HyperReality Mac 版通过 GitHub Release 官方分发：下载压缩包 → 解压拖入「应用程序」→ 启动首航。全程无需命令行，无需额外环境。

01

一键下载

点击页面上方金色按钮，跳转到 GitHub Release 页面，下载最新版 HyperReality-macOS.zip。下载完成后它会出现在你的「下载」文件夹里。

02

解压 · 拖入应用程序

在「下载」文件夹中双击 zip 解压，得到 HyperReality.app，把它拖进「应用程序」（Applications）文件夹——这就是标准 Mac 安装方式，无安装向导、无捆绑。

03

启动首航

从「应用程序」打开 HyperReality，跟随装配检查单完成起飞前检查，设置你的第一条航道护栏——今晚 18:00，夜班班组即可首次出征。

⚠ 首次打开如提示“无法验证开发者”：按住 Control 点按图标 → 打开，即可正常启动（macOS 对独立分发应用的标准流程）。
# 标准 Mac 下载链路（浏览器自动完成，无需手输命令）
① 点击「下载 Mac 版」 → GitHub Release → HyperReality-macOS.zip 开始下载
② 访达 → 下载 → 双击解压 → 将 HyperReality.app 拖入「应用程序」
③ 启动台打开 HyperReality → 装配检查单 → 首条航道护栏 → ✓ 首航就绪

# 偏好命令行的主理人，也可以一行装好：
$ curl -L https://github.com/geniusdapeng-collab/hyperreality-system/releases/latest/download/HyperReality-macOS.zip -o ~/Downloads/HyperReality-macOS.zip

黑匣子 · 全程留痕

APPEND-ONLY EVENT LOG

五元事件库 append-only，留痕覆盖率 100% 为运行时不变量。每一次操作可回放、可归因、可逆向补偿回滚——没有“虚假的胜利播报”。

🛑 紧急制动杆，永远挂在工作台最显眼处

经营不是游戏存档，不能读档重来——所以这套系统的安全设计比任何游戏都重。任意端一键暂停全部 Agent，≤60 秒全端生效（含浏览器动作安全中止）。这是产品级安全承诺，不是装饰。

不确定不执行夜间不确定事项只写「求援」事件，禁止猜测执行——求援 ▲ 不是失败，是战队在呼叫主理人。
无回执不宣称完成关键数字必须来自工具回执；无回执显式标注「未核实」，绝不粉饰。
错误可逆回滚 = 逆向补偿事件序列，原始航行日志永不修改，但航线可以修正。
失败转人工，不甩锅探针失效即停止一切点击转人工接管——任务暂停 ≠ 任务失败。
NEW SPECIES · AI-NATIVE AGENT IM

第一公民不是消息，是「可追责的动作」

传统 IM 把「沟通」数字化了，但没有把「行动」数字化——消息发出去，事还得人去办。Agent IM 是 AI 原生的协作底座：每一个动作都有主体、有授权、有结果、有留痕。

最直观的分水岭是审批卡片：飞书里的审批卡片是外挂的 OA 插件，点一下就跳出 IM、跳进另一个系统；HyperReality 里的审批卡片是原生消息类型，批准手势直接写回事件库成为校准样本。这个差别，就是两个时代的差别。服务对象也换了：传统 IM 服务人，Agent IM 服务 AI——主体换了。人和 AI，在同一个 workspace 协作。

与通用 AI 办公的本质区别

通用 AI 办公助手（WorkBuddy / 千问办公 / QoderWork 等）数字化的是「个人办公任务」；HyperReality 数字化的是「组织经营动作」。这不是功能多寡的差别，是品类差别。

数字化对象个人办公任务：文档、表格、纪要组织经营动作：可追责、可审计、可回放
产品形态桌面客户端 / 个人工作台，一人一助手企业级 IM 底座：人机混编班组同场协作
与 IM 的关系IM 是远程遥控入口（手机指挥电脑）IM 是本体：消息=事件、审批=原生消息类型
协作粒度单人任务拆解执行目标→步骤→技能装配的组织级流水线，夜班值守 7×24
数据归属个人账号 / 云端为主企业本机：数据主权 + 多租户隔离
产出口径交付文档、表格等个人产物经营口径：营收、差评响应时长、挽回订单
一句话：通用 AI 办公让员工的 8 小时更高效；HyperReality 让企业的 24 小时自动运转。二者不冲突——员工可以继续用 WorkBuddy 写文档，HyperReality 在组织层把 AI 编成一支可治理、可度量、可归责的数码班组。
