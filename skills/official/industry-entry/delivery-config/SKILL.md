# 交付配置技能（delivery-config）

## 一、技能定位

三个调研/设计技能的产出是"纸面方案"，本技能是**方案到运行系统的翻译器**：把行业落地方案转化为六装配槽实物，完成客户授权与确认，激活Bundle并交付行业定制版。

**调用时机**：落地向导中技能三产出经客户确认后自动调用；或已有行业Bundle客户（快速通道）在装机向导中选择行业后直接调用。

## 二、输入契约

| 输入项 | 必需 | 说明 |
|--------|------|------|
| 行业落地方案 | 技能三产出（完整通道） | 含SOP、Skills清单、围栏建议、一店一档Schema、对接清单 |
| 已有行业Bundle | 快速通道 | 直接复用 bundles/<slug> 实物，跳过资产生成 |
| 客户特有信息 | 交互式收集 | 一店一档基础信息、系统凭据、围栏阈值确认、通知通道、版本选择 |

## 三、执行流程（六步）

### 步骤① 资产生成（自动）
按方案生成六槽实物草稿：objects/stages枚举、archive.schema、围栏包（阈值取方案建议值）、Agent preset清单、Skill清单、UI用例 → 调用 `createBundleDraft`（packages/base/bundles/assembly.ts）。无需客户输入。

### 步骤② 一店一档初始化（交互）
引导客户填写基础档案：门店/品牌/客群/竞对清单/禁用承诺（forbidden 硬约束优先，L1.6）。**必填**，缺一则档案三要素校验（F3.6/L3.7）不通过。

### 步骤③ 系统授权（交互）
按方案对接清单逐项申请：PMS凭据、OTA账号、通知通道绑定（inapp/钉钉/企微/飞书/Slack）、支付/发票等。**凭据经L4客户Patch注入（cordis.patch.yml），不进Bundle、不写事件明文**（PII脱敏管道复用）。

### 步骤④ 围栏确认（交互）
展示方案建议的基线围栏（如保底价、涨幅上限、退款阈值），客户**只可收紧不可放宽**（单调守卫强制）；每次调整即时 dry-run 回放10条历史事件验证。

### 步骤⑤ 装配检查（自动）
`recheckBundle` 起飞前检查单（archive/enums/tools/fences/ui 五类）+ 全围栏 dry-run。**任一红灯禁止激活**，逐项列出缺失并引导补齐。

### 步骤⑥ 激活交付（审批）
`activateBundle` 走 review 级审批卡片，客户拍板激活 → 生成夜班候选清单（18:00机制）→ 预约次日08:30首份清晨决策包 → 输出"行业定制版交付页"（已装配能力清单/已绑定围栏/已授权系统/下一步建议）。

## 四、能力裁剪激活（版本适配）

激活时按客户版本（PLAN_CAPABILITIES）裁剪能力：community版激活时夜班班组、巡检、Quest自治等能力项显示为"已配置·待升级解锁"，并给出升级提示（复用 PlanForbidden 403+升级提示机制）。**向导全流程不因版本中断**——版本只影响激活时的能力生效范围，不影响调研与配置。

## 五、硬约束

1. 每一步写入五元事件库：谁授权了什么、谁确认了什么阈值、谁批准了激活，全程可审计。
2. 凭据类信息永不进事件明文（Patch注入+脱敏管道）。
3. 激活动作本身过围栏（review级），高危操作不自动放行（L5.4）。
4. 配置过程中发现的能力缺口，自动汇入"平台能力反哺清单"，按反哺上报流程处理（opt-in+预览+脱敏+留痕）。
5. 中断可恢复：向导状态持久化，任意步骤可断点续跑。

## 六、输出校验

- [ ] 六槽实物草稿生成且 recheckBundle 全绿
- [ ] 一店一档三要素（档案+阶段+目标）校验通过
- [ ] 全部凭据走Patch注入，事件库无明文凭据
- [ ] 围栏全部dry-run通过，客户调整方向只紧不松
- [ ] 激活经审批卡片人工拍板
- [ ] 能力缺口已汇入反哺清单
- [ ] 交付页输出且首份决策包已预约
