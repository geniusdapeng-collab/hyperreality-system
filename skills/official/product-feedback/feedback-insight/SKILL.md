# 反哺信息自动收集整理分析技能（feedback-insight）

> 运行位置：**HyperReality团队自有实例**（不在客户实例运行）。客户侧对应能力为"一键上报"（opt-in+预览+脱敏+留痕四红线）。

## 一、技能定位

行业落地过程中产生的"当前HyperReality能力无法消化"的内容（平台能力反哺清单），经客户opt-in上报后汇入团队实例。本技能每日自动分析整理，形成产品迭代优化建议，供产品团队裁决。

## 二、输入

| 输入项 | 说明 |
|--------|------|
| 反哺上报事件流 | 客户实例经HTTPS端点上报（邮件通道为降级）；已脱敏、不含客户经营数据；object_type=feedback 五元事件 |
| 历史反哺清单 | 组织记忆中已沉淀的缺口条目（用于去重与频次统计） |
| 版本发布记录 | CHANGELOG，用于识别"已解决"缺口 |

## 三、执行流程（每日定时，cron触发）

1. **汇聚**：读取上一周期的全部反哺上报事件。
2. **聚类**：按"能力域（语音通道/多模态/剧本运行时/指标口径/IoT/采集治理/数据网络/触达通道/记忆形态/客户端形态/其他）× 缺口类型（机制缺失/槽位不足/阈值不适配/通道未接入）"归类，合并同类项。
3. **频次与趋势**：统计各缺口的上报频次与周期环比；频次高者排前。
4. **关联**：与历史反哺清单关联，标注"新增/持续/已被新版本解决"。
5. **建议生成**：产出《产品迭代建议日报》——新增缺口、高频缺口排序、建议优先级（P0/P1/P2）、建议归口包（packages/base/<域>）。
6. **进审批队列**：日报以review级审批卡片进入团队实例的决断队列，人审后转产品backlog；驳回的原因回流记忆（校准闭环）。

## 四、硬约束

1. 只处理已脱敏报文；发现疑似未脱敏内容（命中PII规则）→ 拒收并写安全事件。
2. 日报是"建议"不是"决策"——任何迭代立项必须经人工审批。
3. 聚类判断与频次统计全程留痕，可回放上溯到原始上报事件。

## 五、输出校验

- [ ] 日报每日定时产出，无缺日（缺日写异常事件）
- [ ] 每条建议可追溯到原始上报事件链
- [ ] 疑似未脱敏报文拦截率100%
- [ ] "已解决"缺口在解决后首个周期内标注闭环
