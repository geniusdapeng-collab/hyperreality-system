# 桌面产品完整性与渲染契约

> 状态：发布门禁级设计；适用于 WorkLoom 基座及全部行业 Bundle。

## 1. 产品交付契约

桌面安装包不是网页容器，而是一个完整、离线可启动的 Agent IM 产品。每个正式包必须同时满足：

1. 首次启动进入当前 Bundle 对应的示例工作区，而不是历史缓存中的其他工作区。
2. 种子数据、岗位编制、技能、首页任务和欢迎话术来自同一个 Bundle 版本。
3. 首装依次展示：织伴数字人开场、行业能力介绍、团队列队仪式、产品首页。
4. 数字人必须是持续运动、可眨眼、可做表情和手势、口型跟随语音的完整人物。静态图片不算通过。
5. 任意时刻只有一条普通语音播放；熔断语音可以明确取消当前语音。页面后台事件不得抢占首装仪式。
6. 升级保留本机配置和 JWT 密钥，并主动清理已失效的前端会话；不得因升级回到旧内容或黑屏。

## 2. 渲染架构

桌面端采用两套真正可交付的渲染后端，而不是“高级效果 + 静态图”：

- `live2d-webgl`：默认数字人后端。Electron 保持硬件加速，使用 Cubism + Pixi 渲染完整 Live2D 人物。
- `vector2d`：WebGL 不可用或 Live2D 初始化失败时启用。使用 SVG/DOM 动画渲染完整人物，保留呼吸、眨眼、视线、情绪、手势和语音口型。
- 团队仪式固定使用独立的 SVG/DOM 动画列队，避免 Live2D/Pixi 与 Three.js 在同页交接 WebGL 上下文时发生跨上下文纹理污染。Three.js 版本只作为开发实验入口，不进入正式发布链路。

主进程不再默认关闭 macOS 硬件加速。`WORKLOOM_SAFE_RENDERING=1` / `--safe-rendering` 只用于已知 GPU 驱动故障的设备，并强制选择 `vector2d`。两种后端的页面业务结构和文字内容完全相同。

## 3. 语音编排

`VoiceEngine` 是唯一播放入口：

- 所有播报进入单消费者队列；下一条只能在上一条收到 `onend`/`onerror` 后开始。
- 超时仅作为浏览器事件丢失的 watchdog，不作为正常分段计时。
- `fuse` 是唯一允许抢占的优先级，抢占结果为 `cancelled`。
- 欢迎仪式持有独占会话。持有期间，晨会、环境播报和普通事件只发字幕，不得入语音队列。
- 用户点击快进会明确取消当前段，再开始下一段；自动推进永远等待真实语音结束。

## 4. 首装状态机

```
bootstrap → session validated → welcome/mate → team/entrance
          → team/dance → team/ribbon → summary modal → product home
```

状态迁移只能由当前状态的完成事件触发。组件卸载时取消自己的计时器和语音会话，旧状态的异步回调不得推进新状态。

## 5. 发布门禁

每个安装包在上传 Release 前必须在“打包后的可执行文件”上完成：

1. 后端冒烟：解包、数据库初始化、迁移、Bundle 种子、服务健康检查。
2. 渲染冒烟：真实创建 BrowserWindow，等待 `data-product-ready=true` 和 `data-avatar-ready=true`。
3. 双后端冒烟：默认数字人必须得到 `live2d-webgl`；安全模式数字人必须得到 `vector2d`；两者的团队仪式都必须得到独立的动态 `vector2d` 舞台。
4. 数字人动作检查：模型声明的嘴型/眨眼参数必须真实写入且读取成功；至少完成一次开口、一次完整眨眼和一次已被 MotionManager 接受的手势动作。只检查“canvas 存在”或“人物轻微晃动”不算通过。
5. 真实状态机检查：验收必须按用户交互依次推进 `enter → intro → system → detail → bridge → exiting → entrance`，禁止用 `setPhase` 等测试钩子直接跳到团队态。
6. 画面检查：欢迎页和团队页分别保存截图并检测亮度方差、人物包围盒和关键文本，纯黑/纯色画面直接失败。
7. 内容检查：页面报告的 Bundle id、工作区名、岗位数、技能数与构建清单一致；团队画面人数必须等于 Bundle 岗位数加 CEO。
8. 语音单元测试：正常播报绝不重叠；快进产生取消；熔断是唯一抢占路径；系统 TTS 不提供 `boundary` 时仍必须启用文本节律口型。

Actions 必须上传两种渲染模式的截图和 JSON 探针结果。任一门禁失败，不创建或更新 Release。

## 6. 基座同步边界

渲染后端、语音编排、桌面主进程、升级/会话逻辑和发布门禁属于基座文件，通过 base-sync 同步到全部产品。行业仓只维护 Bundle 数据、岗位、技能、文案和品牌资产。同步后仍需逐仓执行内容清单和安装包冒烟，不能以“同源代码”替代成品验收。
