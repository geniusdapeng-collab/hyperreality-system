# 数字员工命名规范（F-NAME1）

## 1. 概念关系（对外统一口径）

| 词 | 定位 | 出现场合 |
|---|---|---|
| **数字员工** | 组织里的「人」：有名字、有官衔、有形象、有编制 | 所有用户界面、汇报视图、对外文案 |
| **Agent** | 数字员工的执行本体（技术说法） | 仅代码、API、技术文档；**界面永不出现** |
| **技能（Skill）** | 员工学会的本事，可装配/卸载 | 技能中心 |

一句话：**数字员工是"人"，Agent 是这个人的"大脑与双手"，技能是他学会的"本事"。**

## 2. 命名结构

每个数字员工的名字由两部分组成：

```
官衔（岗位角色） · 人名（人格化花名）
例：市场侦察官·沈听澜、财务司库官·秦清晏
```

- **官衔**：职能 + 官/员/师/长/总监，动宾结构（市场侦察官、客房管家官）。
  由行业 bundle `presets/*.yml` 的 `name` 字段承载。
- **人名**：2-3 字中文虚构名。无生僻字、无名人同名、无英文、无数字。
  由 `apps/web/src/lib/naming.ts` 的 `PERSONA_MAP` 登记，或哈希稳定分配。

## 3. 使用规则

| 场景 | 展示 |
|---|---|
| 汇报视图 / 3D 职场名牌 | 人名为主，官衔副标题（或「官衔·人名」） |
| 成员列表 / 档案 | 官衔·人名 |
| 消息 / 日报正文 | 官衔（行文简洁） |
| 技术日志 / API | preset_key（英文 ID 仅限此处） |

## 4. 新增员工（用户创建 / 系统自动生成）

1. 官衔必须来自行业 bundle 的岗位词典，禁止自由输入「xxx-Agent」「助手1号」；
2. 人名由 `personaOf(preset_key)` 稳定分配——同一 preset_key 永远同一人名，
   不会每次随机跳变；登记册未收录时按 djb2 哈希从 30 姓 × 40 名库稳定选取；
3. 行业版扩充：在 bundle presets 登记官衔，在 `PERSONA_MAP` 追加人名即可。

## 5. 禁止清单

- ❌ 任何 `Agent` 后缀/前缀（如"××Agent"式的旧命名、Agent-01）
- ❌ 英文名、拼音、编号名（Robot-03、assistant）
- ❌ 「数字员工」直接当名字用（它是类别词，不是名字）
- ❌ 生僻字、名人同名、网络梗名
