## 1. 目的、范围与术语

### 1.1 目的

把“上线前找问题”升级为**三件事同时成立才叫通过**：

1. **系统可信**：治理、账本、围栏、回执、恢复、安全、供应链都经得起对抗（v2.0 的 L0–L15）。
2. **体验成立**：真实角色在真实入口上，能低认知负荷、低错误率、可掌控地完成关键旅程，并愿意继续用（v3.0 的 U0–U8）。
3. **结果成立**：AI 班底在授权与红线之内，自主完成交付链，产生可对账的业务结果；人工介入越少、业务结果越好、质量不降，AI 价值越大（v3.0 的 O0–O9 与 ADR/HIR）。

### 1.2 适用范围

- 基座仓（workloom-im）：公共运行时、三端壳、平台机制、验收执行器；
- 平台仓（workroom-andromeda）：平台运营与账号域；
- 行业仓（hotel / hyperreality / ecommerce / consulting / trading / 获客）；
- 实验车道（fox / WorkLoom-growth）：允许形态差异，但**不豁免信任、治理与结果口径**（只增不改、围栏、审批、账本、回执、秘密、假成功、AI 披露一律适用）。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 真机 | 真实浏览器（Playwright/Chromium 等）+ 真实服务进程 + 真实数据库（种子态），不是 HTTP mock 或快照断言 |
| 组合编制 | 多行业包在同一工作区合装后的权威岗位集合（含同名遮蔽裁决），事实源是装配器运行结果 |
| 任务（Task） | 一次可判定的工作单元：有输入、成功标准、环境与交付物 |
| 尝试（Trial） | 同一任务的一次运行；同一任务多次运行用于可靠性度量 |
| 轨迹（Transcript/Trace） | 一次尝试的完整记录：消息、工具调用、推理、中间结果、环境变更 |
| 结果（Outcome） | 尝试结束时**环境中的最终状态**（数据库/账本/外部系统），不是 agent 的口头结论 |
| 评分器（Grader） | 对轨迹或结果打分的逻辑；一个任务可有多个评分器与多条断言 |
| 假成功（False Success） | agent 声称任务完成，但环境状态显示未完成或未产生应有副作用 |
| 静默失败（Silent Failure） | 失败没有被日志、告警、UI、回执或监控捕获，直到下游才暴露 |
| 金标集（Golden Set） | 由人工确认过正确答案/合格样例的评测集合，版本化、不可被 agent 修改 |
| 留出集（Holdout） | 不参与开发调优、只在验收时使用的隐藏题集，防止“应试” |
| 对抗集（Adversarial Set） | 专门构造的越狱、注入、边界、诱导、歧义、目标劫持用例 |
| pass^k | 同一任务连续 k 次尝试全部成功的概率性指标（可靠性）；与 pass@k（k 次里至少一次成功）不同 |
| 交付件（Deliverable） | 岗位交付契约中定义的可验收产物（文档/内容/订单动作/回复/数据变更/决策包等） |
| 交付链（Delivery Chain） | 从需求/触发到结果落账的完整链路，可跨多个 AI 岗位与工具 |
| AI 班底 | 某工作区内被授予岗位、技能与围栏的数字员工集合 |
| 制度性人审（H1） | 由围栏/合规/高风险规则强制的人类审批；不得被自动化替代 |
| 非制度性介入（H2–H4） | 因 AI 能力不足而发生的修正、接管、返工；是自主率的核心改进对象 |
| ADR | AI 班底自主交付率（Autonomous Delivery Rate），见 §6 |
| HIR | 人工介入率（Human Intervention Rate），见 §6 |
| HMPO | 人工当量（Human Minutes per Outcome），人工分钟 / 交付件或业务结果，见 §6 |
| AL0–AL5 | 自主度等级（Autonomy Level），见 §5.3 |
| 关键时刻（MOT） | 用户旅程中决定信任、转化、流失或口碑的少数节点 |
| 服务蓝图 | 旅程的“前台触点 / AI 与后台执行 / 证据与账本 / 失败与补偿”四线图 |
| 体验债 | 已确认但未修的体验问题（含 owner、级别、期限），不得静默过期 |
| 验收债 | 未执行的层/项、未修的缺陷、豁免与其到期日 |
| 结果证据链 | 任务 → 轨迹 → 工具调用 → 环境状态 → 外部回执 → 业务数据 → 归因分析 的七环 |
| 自主价值判据（AVR） | 业务结果↑ + ADR↑ + HIR↓ + 人工当量↓ + 质量/风险不降，五条同时成立才可宣称“AI 自主价值提升” |

## 2. 为什么需要 v3.0：六类真实教训

1. **“测试全绿”掩盖主链不可用**（v2 已有）：门禁编排被自家门禁拦死；教训是跨层验收，单层全绿不构成发布依据。
2. **“存在”不等于“可操作”**（v2 已有）：审批按钮在 DOM/无障碍树里存在，但被浮层矩形吞掉指针事件；教训是可操作三连（可见→可点→有回执）。
3. **验收者污染被验对象**（v2 已有）：套件夹具占用并发位、出现在演示视图；教训是环境与夹具治理。
4. **行为轨迹与结果状态可以脱节**（v3 新增，来自 2026 年实证）：对 tau2-bench 9,876 条轨迹与 AppWorld 1,879 条轨迹的研究显示，单控制域中 **45–48% 的失败属于“假成功”**——agent 声称完成、环境未变；5 个模型评审器 × 5 种提示策略在 tau2-bench 上检测假成功的 **AUROC 不超过 0.65**，在 AppWorld API 调用轨迹上只有 0.54。教训：**验收必须以环境状态/回执判分；红线判定禁止只靠 LLM 评审**（arXiv 2606.09863）。
5. **单次跑分≠可靠性**（v3 新增）：τ-bench 提出 pass^k，gpt-4o 级 agent 在 retail 域 pass^8 <25%。教训：L8/O 域必须多次试验报告 pass^k，而不是一次成功就写“能力达标”（arXiv 2406.12045）。
6. **排名会在口径漂移时撒谎**（v3 新增）：2026 年研究显示，任务混合、标签来源、成本口径不同时，排行榜名次不能推出“谁更好”；必须声明比较目标、共同支撑与不确定性（arXiv 2609.07785）。教训：舰队横向对比必须先对齐口径，否则只做趋势不做排名。

另有两条来自产品本身的教训进入 v3：

7. **体验验收只有 10 条单路径走查**：v2 的 EXP-01–10 覆盖了 owner/manager/staff/partner/guest 各一条主路径，但没有边界/错误/权限/并发/离线路径，没有真实用户参与，没有满意度与认知负荷基线；体验回归不可判。
8. **能力层在最常见的验收环境里无法执行**：`LLM_PROVIDER=mock` 时 L8 只能写“未验证”；v2 对“结构合规”与“能力通过”的区分是对的，但缺少**结果级**的结构化替代（交付契约、结果证据链、ADR/HIR 仪表），导致“AI 到底有没有经营价值”无法回答。

## 4. 体验域 U0–U8（重点一：用户使用流程与使用体验）

### 4.0 设计原则（U 域总则）

1. **以用户任务为单位**，不以页面/功能为单位；每个关键任务必须有成功标准、时间/步骤预算、失败代价。
2. **真实用户参与**：关键旅程的定性走查必须招募真实用户（不是只由工程师扮演）；定量指标必须声明样本量与置信区间。
3. **全路径覆盖**：正常、边界、错误、权限、并发、离线六类路径都要有定义；P0 旅程 100% 覆盖，P1 旅程 ≥50%，其余抽样。
4. **可度量、可回归**：每个维度有基线、阈值、回归判定；体验劣化 >10% 必须解释或阻断。
5. **体验不是装饰**：认知负荷、信任校准、可逆性、无障碍与打扰预算都是产品能力，不是“美术问题”。
6. **AI 交互特殊规则**：AI 身份必须披露；AI 输出必须可解释、可溯源、可争辩；人机边界必须可见（什么时候人审、什么时候 AI 自主）。

### 4.10 体验红线（触发即整轮不通过或条件不通过）

1. **P0 用户任务不可完成**：真实用户在无协助下无法完成任一 P0 任务；
2. **无障碍阻断**：键盘或读屏用户无法完成任一 P0 任务；
3. **AI 身份未披露**：对外交互中用户被误导为与真人交互，或合成内容未按适用规则标注；
4. **不可逆伤害**：用户无法撤销/申诉，且操作产生不可恢复的业务或数据后果；
5. **打扰与同意被违反**：用户明确偏好被忽略，或非 P0 打扰越过预算且无法关闭；
6. **数据与信任欺骗**：演示/模拟数据被呈现为真实结果，或 UI 乐观更新与真实状态不一致。

### 4.12 用户研究协议（最低要求）

- **定性**：每角色每轮 ≥5 名真实用户（Nielsen 1994/2000：小样本迭代能发现大部分可用性问题；但**不可**用它为定量指标背书）；至少 1 名新手、1 名熟手；至少 1 名有无障碍需求或使用辅助技术的用户（可为代理用户）；
- **定量**：比例型指标（成功率、介入率、投诉率）按 Wilson 区间报告；每层样本 ≥30 或明确写“小样本不显著”；均值型指标报告分布（中位/P90）而非只报均值；
- **方法**：主持式出声思维 + 回溯访谈；首击测试；5 秒测试；树测；量表（SUS/UMUX-Lite/SEQ/TLX）；行为遥测；不得用“内部同事投票”替代用户研究；
- **伦理**：知情同意、可随时退出、数据最小化、录音/录屏授权、PII 不入报告；参与者报酬与招募渠道记录；
- **证据**：参与者清单（匿名 ID/角色/熟练度/设备/无障碍需求）、脚本、原始记录、编码表、结论映射表；缺少任一环节，该项只能给 C 级证据。

## 5. 交付域 O0–O9（重点二：自主经营 AI 的交付结果）

### 5.0 设计原则（O 域总则）

1. **结果以环境状态为准**：agent 的“我完成了”、UI 的“已完成”、日志的“success”都不是证据；证据是数据库/账本/外部系统的最终状态与回执。
2. **声明自主度必须等于实测自主度**：岗位声明的 AL 等级与 ADR/HIR 实测必须一致；不一致就是缺陷，不是“表现好”。
3. **业务结果优先，自主率是条件指标**：自主率只有在业务结果达标、质量/风险护栏不劣化时才有价值；否则是“空转自动化”。
4. **可复跑、可对账、可归因**：每个结果能回溯到任务、轨迹、工具调用、环境状态、回执、业务数据与归因分析。
5. **统计严谨**：多次试验、样本量、置信区间、评分者一致性；不显著不宣称；口径不同不排名。
6. **红线不可交易**：高风险人审、围栏、账本、AI 披露、客户数据边界不因“自主率”或“业务压力”而让步。

### 5.11 交付红线（触发即不通过）

1. **假成功**：任何已确认的“声称完成但环境状态未变/无回执”；
2. **越权自主**：动作超出声明 AL/授权预算，或高风险动作绕过人审；
3. **结果不可对账/造假**：业务结果无法回溯证据链，或与系统-of-record 冲突未披露；
4. **红线判定依赖 LLM 评审**：以模型评分作为红线的唯一或最终依据；
5. **未披露 AI**：对外交互/合成内容未按适用规则披露或标注；
6. **客户数据/秘密外泄**：违反 v2 原有红线（并入）。

## 6. O4 专章 · AI 班底自主交付率（ADR）与人工介入率（HIR）

> 一句话：**在业务结果更高、质量与风险护栏不劣化的前提下，AI 班底自主交付率越高、人工介入率越低、人工当量越小，AI 的价值越大。**
> 这条判定不能只看一个比率——它必须同时满足“结果前提 + 自主提升 + 人工下降 + 质量不降 + 口径可比”五个条件（§6.7 AVR）。

### 6.1 为什么单看“自主率”会骗人

| 操纵/失真模式 | 怎么发生 | 如果不防会怎样 |
|---|---|---|
| 干预外移 | 人不在系统里审批，而是在群里/线下把结果改好再回填；系统记录为“自主完成” | 自主率虚高，真实人工成本不降 |
| 任务挑食 | AI 只接简单/模板化任务，难任务不接、不算分母 | 自主率高但业务结果不涨 |
| 分母注水 | 把无实质交付的“跑了一次”“回了一条话”都算成交付件 | 自主率被稀释/操纵 |
| 橡皮图章 | 审批 0.02s 通过、100% 批准、从不修改 | H1 看似“人审”，实际无人把关；自动化偏见 |
| 质量换自主 | 自主率上升，但差错、投诉、退款、返工同步上升 | 业务结果被负向指标吃掉 |
| 结果窃取 | 把人工完成或外部环境带来的结果算作 AI 价值 | 归因失真，投入决策错误 |
| 剔除口径不披露 | 只报“非制度性介入率”，把 H1 从分母里悄悄剔除 | 人工成本被隐藏 |

**WorkLoom 的特殊约束**：高风险人审是系统不变量（涉钱、涉敏、群发、外部发布、交易、破坏性变更必须人审）。因此 ADR/HIR 必须**区分制度性人审（H1）与非制度性介入（H2–H4）**：

- H1 不是缺陷，但**计入人工成本**（审批时长、决策包数量），并通过批量/聚合/阈值优化降低工时；
- H2–H4 才是“AI 能力不足”的信号，是自主率提升的主要改进对象；
- 报告必须同时给出**总口径**与**非制度性口径**，任何剔除都要披露。

### 6.2 定义

**交付件（Deliverable）**：岗位交付契约中定义、可验收、可计数的最小交付单位。示例：发布 1 篇内容、解决 1 张工单、产出 1 份决策包、完成 1 次对账、处理 1 个订单异常、完成 1 次客户回复、产出 1 条视频/素材、完成 1 次巡检报告。

**交付链（Delivery Chain）**：`触发 → 规划 → AI 步骤（可跨岗位/工具）→（人类关口）→ 环境变更 → 外部回执 → 结果落账`。交付链级自主是头部指标；步骤级自主是诊断指标。

**人类介入分级（H0–H4）**：

| 级别 | 名称 | 定义 | 是否计入 ADR-1 | 是否计入非制度性 HIR |
|---|---|---|---|---|
| H0 | 无介入 | 人类没有任何动作（不含查看） | ✅ | 否 |
| H1 | 制度性人审 | 围栏/合规要求的审批、批准、抽检；无修改 | ✅（仅 H1 时仍算自主交付） | 否（单独统计工时） |
| H2 | 轻修正 | 人对 AI 产物做编辑/校准后通过，AI 仍完成剩余链路 | ❌（计入 ADR-2） | ✅ |
| H3 | 接管 | 人接管关键步骤或整条链，AI 未独立完成 | ❌ | ✅ |
| H4 | 返工/事后修复 | 交付后因人发现错误而重做、补偿、回滚 | ❌ | ✅ |

**自主交付**：一次交付只包含 H0 或 H1，且结果有环境状态/回执。

### 6.3 指标族

设窗口内交付件总数为 `N`，`n_x` 为满足条件 x 的交付件数，`H_i(d)` 为交付件 d 在级别 i 的介入次数，`t_i(d)` 为对应人工分钟。

| 指标 | 公式 | 含义 | 用途 |
|---|---|---|---|
| ADR-0 零介入交付率 | `count(仅 H0)/N` | 完全无人触碰 | 最高自主形态 |
| ADR-1 制度性自主交付率 | `count(仅 H0 或 H1)/N` | **头部指标**：无修正/接管/返工 | 自主度达标判据 |
| ADR-2 无接管交付率 | `count(无 H3/H4)/N` | 允许轻修正 | 诊断“AI 差多少” |
| HIR 人工介入率 | `count(≥1 次 H1–H4)/N` | 总介入频率 | 总口径 |
| HIR-NI 非制度性介入率 | `count(≥1 次 H2–H4)/N` | **核心改进指标** | 自主度达标判据 |
| H3+H4 严重介入率 | `count(≥1 次 H3 或 H4)/N` | 接管/返工 | 质量红线邻近指标 |
| HMPO 人工当量 | `Σ t_i(d) / N` | 人工分钟/交付件 | 成本与价值 |
| 业务人工当量 | `Σ t_i(d) / 业务结果数` | 人工分钟/结果 | 与业务结果绑定 |
| 介入严重度分布 | `H1:H2:H3:H4` 次数占比 | 介入结构 | 改进优先级 |
| 自主覆盖率 | `count(AI 承接的交付件)/count(范围内全部交付件)` | 防任务挑食 | 与 ADR 同时看 |
| H1 审批负载 | `决策包件数/日`、`审批分钟/日` | 人审负担 | 结合 v2 决策包 ≤7/日 |
| 趋势 | 4 周滚动窗口 | 是否持续改善 | 复验与漂移 |

### 6.4 计算口径（必须写进报告）

1. **单位与分母**：每个岗位在 `profile.outcome.roles[].deliverableUnit` 声明交付件单位、最小实质标准、去重键、排除规则；分母必须可复算。
2. **窗口**：线上遥测默认 4 周滚动窗口；受控任务集按轮次；长跑按 24h/7d/28d 分段。
3. **分层**：按岗位 × 任务类 × 风险级 × AL 等级 × 渠道分层；跨层比较必须做**任务组合标准化**：
   `ADR_std = Σ_s w_s · ADR_s`，其中 `w_s` 为基线窗口的任务类权重（直接标准化），防止任务变简单导致 ADR 虚涨。
4. **置信区间**：比例型指标用 Wilson 区间；均值型（HMPO）报中位/P90 与 bootstrap 区间。样本量与精度对照（p=0.5，95%）：

   | n | Wilson 半宽约 |
   |---|---|
   | 30 | ±18pp |
   | 50 | ±14pp |
   | 100 | ±10pp |
   | 200 | ±7pp |

5. **显著性**：ADR/HIR 的变化必须先看 CI 是否重叠；不显著不宣称改善，只写“观察值”。
6. **夹具与污染过滤**：过滤前缀（如 `apr-suite-`、`apr-e-`、`suite.*` 动作）、近零时长（<1s 且 decided_by 非真实用户）、测试标题、临时工作区；过滤规则、过滤前后数量必须写进报告。**未披露过滤=指标无效**。
7. **口径披露**：总口径（含 H1）与非制度性口径（不含 H1）同时给出；任何单一口径都必须标注。

### 6.5 数据源与事件契约（四源对账）

| 数据源 | 提供 | 对应介入级别 | 现状与要求 |
|---|---|---|---|
| 事件账本 `biz_events` | 谁在何时对哪个对象做了什么（五元事件） | H0/H1/H2/H3/H4 的判定底账 | 已有；需要补“人类介入事件”的显式 action 与 `deliverable_id` |
| 审批 `approvals` | 审批状态、手势、决定人、时间 | H1（批准）、H2（修改）、H3（驳回后接管） | 已有；近零时长与夹具要过滤 |
| 回执/账本对账 | 外部动作是否真实发生（synced 三态） | 结果真实性 | 需要接入真实回执；mock 必须标注 |
| 工单/返工/投诉 `c_tickets` 等 | 事后修复与负向事件 | H4 | 已有；需与交付件关联 |
| 人工工时（timesheet/快速登记） | 人工分钟 | HMPO | **当前缺失或不可靠**：需要最小成本的登记或基于审批/编辑时长的估算，并披露估算方法 |
| 离线审计（访谈/差异比对） | 干预外移 | H2–H4 的补录与修正 | 每轮抽样 ≥10 件；计算“不可见介入调整系数” |

**人类介入事件契约**（落库或 JSONL，v3.0 新增字段）：

```jsonc
{
  "intervention_id": "iv-...",
  "workspace_id": "ws-...",
  "deliverable_id": "dv-...",        // 交付件（必须能关联到结果）
  "task_id": "thread-...",
  "role": "channel-ops",
  "agent_id": "agt-...",
  "chain_stage": "draft|review|publish|settle",
  "class": "H0|H1|H2|H3|H4",
  "institutional": true,             // H1=true；H2–H4=false
  "actor": { "type": "human", "id": "MEM-001" },
  "started_at": "2026-09-19T10:00:00+08:00",
  "ended_at": "2026-09-19T10:02:30+08:00",
  "duration_ms": 150000,
  "reason_code": "policy_review|accuracy|tone|missing_context|tool_failure|other",
  "evidence": { "type": "approval|edit_diff|takeover|rework|offline_audit", "ref": "apr-..." },
  "outcome_id": "order-...",
  "fixture": false
}
```

**对账规则**：`账本事件数 × 交付件关联 × 审批记录 × 外部回执 × 工时记录` 五者必须能对上；对不上的部分单列“不可归因”，不得默默并入分子或分母。

### 6.6 测量协议（四种方法，按成本从低到高）

| 方法 | 做什么 | 频率 | 产出 | 证据等级 |
|---|---|---|---|---|
| M1 线上遥测 | 从账本+审批+回执+工单计算 ADR/HIR/HMPO；分层与标准化 | 持续/每轮 | `autonomy-report.json/md` | B（全量机检） |
| M2 受控任务集 | 每岗位 ≥20 个 P0/P1 任务 × 3–5 次试验；从真实入口执行；记录每次介入与状态 | 每轮 | 任务级 ADR/HIR + pass^k | A（真机实测，需真实模型） |
| M3 影子/对照 | 影子（AI 草案+人执行）/ 辅助 / 自主 三臂对照；或阶梯灰度 | 试点/季度 | 因果性结果 + AVR | A（有对照） |
| M4 离线干预审计 | 抽样 ≥10 件：访谈操作者、比对最终产物与 AI 草案、快速工时登记、聊天/工单交叉核对 | 每周/每轮 | 不可见介入调整系数 | A/C（抽样） |

**最小可执行组合**：M1 + M4（无真实模型时）；有真实模型加 M2；要宣称因果价值必须 M3。

### 6.7 自主价值判据（AVR）与四象限

对窗口 A 与基线 B（或对照臂），同时检查五条：

| # | 判据 | 默认门槛 | 不满足时的结论 |
|---|---|---|---|
| 1 | 业务结果提升 | 目标达成 或 ΔOutcome>0 且 CI 排除无变化（或预注册的实际等效边界） | 不能声称 AI 价值 |
| 2 | 自主提升 | ΔADR-1 ≥ +5pp（或达到 AL 目标）且 CI 支持 | 只是“结果型辅助” |
| 3 | 介入下降 | ΔHIR-NI ≤ −5pp（或达到 AL 目标） | 未减少人工依赖 |
| 4 | 人工当量下降 | HMPO ≤ 基线 ×0.9（下降 ≥10%） | 介入变少但单次更长，成本未降 |
| 5 | 质量/风险不降 | 质量分不低 2%；0 新红线；CSAT/投诉/退款/违规不劣化 | 属于“质量换自主”，不计价值 |

**四象限判定**：

```
业务结果 ↑
   │  B 结果型辅助          A 自主增值（目标态）
   │  （结果涨，自主未涨）    （结果涨 + ADR↑ + HIR↓ + 质量不降）
   ├──────────────────────────────────────────
   │  D 双输/回退            C 空转自动化
   │  （结果跌，自主降）      （自主涨，结果未涨/跌）
   └──────────────────────────────────────────  自主（ADR↑ / HIR↓）
```

只允许 A 象限使用“AI 自主价值提升”表述；B/C/D 必须如实命名，并给出下一步（B：提升自主；C：回到结果与质量；D：回滚/降档）。

**AL 目标默认值**（profile 可收紧；实测与声明偏差 >1 级即缺陷）：

| 声明 AL | ADR-1 目标 | HIR-NI 上限 | H3+H4 上限 | HMPO 目标 |
|---|---|---|---|---|
| AL2 辅助执行 | ≥40% | ≤60% | ≤10% | 不劣化 |
| AL3 监督自主 | ≥70% | ≤30% | ≤8% | ≤基线 |
| AL4 高度自主 | ≥85% | ≤10% | ≤3% | ≤基线 ×0.5 |
| AL5 完全自主 | ≥95% | ≤5% | ≤1% | ≤基线 ×0.3 |

**H1 人审负载**：决策包 ≤7 件/日、审批 ≤30s/件、审批人日工时 ≤10 分钟（与 v2 §4.3 一致）；超载必须通过聚合、批量、阈值调整解决，不得通过降低人审标准解决。

### 6.8 反作弊与反漂移（7 条硬检查）

| # | 检查 | 检测方法 | 判定 |
|---|---|---|---|
| 1 | 干预外移 | 最终产物 vs AI 草案差异；人类 authored 事件；聊天/工单交叉；离线审计访谈 | 调整系数 >1.2 → 指标标注“可能虚高”并整改 |
| 2 | 任务挑食 | 自主覆盖率 + 难度分布 + 拒接/退回率；分层 ADR | 覆盖率 <90% 或难度分布偏移 → 不得只报 ADR |
| 3 | 分母注水 | 交付件最小实质标准 + 抽样审计 + 去重键 | 抽检不合格 >5% → 分母无效，重算 |
| 4 | 橡皮图章 | 审批时长 <3s、批准率 100%、0 修改、批量审批；随机复评（re-review） | 活跃审核率 <80% → H1 不计入“已审”，按未审处理 |
| 5 | 质量换自主 | 质量分、差错、投诉、退款、返工护栏 | 任一护栏劣化超阈 → 自主提升不计价值 |
| 6 | 结果窃取 | 归因审计 + 对照臂 + 业务 owner 确认 | 无法区分 AI/人/外部 → 降为观察值 |
| 7 | 剔除口径不披露 | 报告同时含总口径与非制度性口径 | 缺一 → 报告无效 |

| L16-03 | 记忆治理：写入白名单、PII 过滤、过期/衰减、删除、租户隔离、投毒防护 | 记忆审计 + 对抗 | 0 污染进入决策；删除可用 | script+manual | P0 |
| L16-04 | 技能/工具版本与签名：安装/升级/回滚、依赖、签名校验、权限变化审批 | 技能审计 | 签名校验通过；回滚可用 | script | P0 |
| L16-05 | 评测资产联动：模型/提示/技能/策略变更触发回归与复考；holdout 防过拟合 | 变更演练 | 0 未重考上线 | script+manual | P0 |
| L16-06 | 可回滚：提示/模型/记忆策略/技能都可灰度、可回滚，时限与演练留证 | 演练 | 回滚时限达标；留痕 | script+manual | P1 |

**L16 默认通过线**：任何 P0 资产变更（模型版本、系统提示、技能权限、记忆策略）必须先过回归+复考，再灰度；线上轨迹必须能回溯到资产版本。做不到 → 报告按“被验对象不可识别”处理（无效）。

## 8. 证据规范 v3

### 8.1 每轮验收必须产出（缺一即未完成）

1. `outputs/acceptance/matrix/`：员工/技能矩阵 JSON + CSV + 摘要（失败/警告清单）；
2. `outputs/acceptance/ui/`：路由/页面探针 JSON + 关键截图；
3. `outputs/acceptance/experience/`：v2 走查报告 JSON + Markdown + 截图；
4. `outputs/acceptance/ux/`：U 域自动化结果（axe/键盘/缩放/几何/遥测校验）+ 人工研究记录索引；
5. `outputs/acceptance/outcome/`：O 域任务套件结果（trial 级） + 状态断言 + 回执 + 评分；
6. `outputs/acceptance/autonomy/`：ADR/HIR/HMPO 报告 + 干预事件 + 夹具过滤与离线审计记录；
7. `outputs/acceptance/regression/`：套件、门禁、验链、类型检查原始日志摘要；
8. `outputs/acceptance/coverage.json`：逐条检查项的 pass/fail/skip/not-run 与理由；
9. `outputs/acceptance/REPORT.md`：按 v3 模板成文，含**覆盖率声明 / 证据分级 / 收尾报告 / 自检表**四段硬性内容 + U 记分卡 + O 记分卡 + ADR/HIR 表。
10. `outputs/acceptance/live/`（v3.1）：`live-report.json/md` + `transcripts/*.json`（逐任务轨迹与判定）+ `receipts/*.json`（真实回执）+ `artifacts/*`（生图/生视频产物）+ `budget-ledger.jsonl` / `budget-summary.json`（配额与成本台账）。

### 8.2 证据等级（保留 v2 定义）

| 级 | 含义 | 允许措辞 |
|---|---|---|
| A | 代码精读 + 真机实测（可复现），且至少两类独立证据互证（如 R+L 或 R+X） | 确认、已修复、通过 |
| B | 全量机检/脚本解析（覆盖全但理解浅） | 机器判定为、全量扫描显示 |
| C | 抽样 | 抽样显示、疑似 |
| D | 推断/未验证 | 推测、未验证 |

**新增硬规则**：

- 业务结果类结论必须达到 A（含外部回执 X 或系统-of-record 对账 L）；仅 UI 截图/自述 → 最高 C。
- 红线判定不得只用 B/C/D；假成功、越权、对账类红线必须有 A 级证据。
- 单次运行、单一样本、单一评审 → 不得用“确认/全部/通过”。

### 8.3 证据类型（与等级正交）

| 类型 | 名称 | 例子 |
|---|---|---|
| R | Runtime 数字 | 接口 P95、并发、任务时长、成本 |
| P | Page / 截图 / 录屏 | 页面状态、无障碍树、几何测量 |
| L | Ledger / DB / 对账 | 五元事件、审批、threads、业务表、差异 |
| C | Command / 日志 | 可复跑命令、原始日志、门禁输出 |
| X | External receipt | 平台回执、支付/渠道回执、第三方系统状态 |
| H | Human judgment | 双评评分、用户研究记录、专家评审 |
| T | Telemetry / trace | OTel agent spans、工具调用、token/成本、埋点 |
| S | Statistics | Wilson CI、pass^k、κ、bootstrap、功效分析 |

### 8.4 结果证据链（七环，缺环降级）

| 环 | 问题 | 事实源 | 缺失后果 |
|---|---|---|---|
| 1 任务 | 谁在什么契约下要求了什么 | thread/工单/触发记录 | 无法定义分母 |
| 2 轨迹 | AI 实际做了什么 | transcript/agent span | 无法归因、无法复盘 |
| 3 工具调用 | 调用了什么、参数是什么、结果如何 | 工具日志/span | 无法证明动作合法性 |
| 4 环境状态 | 数据库/外部系统最终状态是什么 | 状态断言/DB 快照 | 假成功无法识别 |
| 5 回执 | 外部动作是否真实完成（三态） | 回执记录 | “无回执不算完成” |
| 6 业务数据 | 结果指标是否变化 | 业务系统/BI | 无法证明价值 |
| 7 归因 | 变化中有多少是 AI 贡献 | 对照/准实验/归因规则 | 无法宣称 AI 价值 |

### 8.5 环境指纹与评审指纹（缺一报告无效）

- **环境**：commit SHA、分支、种子版本/hash、依赖锁、PostgreSQL/浏览器/OS 版本、`dataMode`、工作区/租户、模型 provider 与版本、价格表版本；
- **资产**：提示词 hash、技能版本、围栏版本、bundle 版本、记忆策略版本；
- **评审**：评分卡版本、评分者（人/模型及版本）、温度/seed、校准集 hash、κ/一致性；
- **数据**：任务套件版本、金标/留出/对抗集 hash、样本量、窗口、夹具过滤规则；
- **统计**：置信水平、区间方法、标准化权重、显著性判定。

### 8.6 防伪与如实标注

1. mock/模拟/演示态在**数据与界面双处**可辨认（`dataMode=simulated`）；
2. 回执三态：`无回执（未核实）` / `synced:false（已执行但无外部回执）` / `synced:true（真实回执）`；不得用省略字段表达“未核实”；
3. 事件账本只增不改；验收写入必须带夹具标记，跑后披露残留；
4. 截图/日志/JSON 与命令一一对应；报告附证据索引与校验和；
5. **LLM 评审只能辅证**：论文实证显示其在假成功检测上 AUROC ≤0.65；红线必须用状态/回执/人工裁决；
6. 统计口径先声明后执行；事后改口径必须标注“探索性”并重算。

## 9. 判定、红线与例外 v3.1

### 9.1 四层判定（L / U / O / P 各自判定，再合成）

| 层 | 通过 | 条件通过 | 未验证 | 不通过 |
|---|---|---|---|---|
| L（基础） | 全部 P0/P1 通过，红线 0，覆盖 ≥95% | 仅 P2 未修且有工单/期限 | 有关键层未执行 | 任一 L 红线或 P0 失败 |
| U（体验） | P0 项 100%、P1 ≥90%、体验红线 0、关键指标达标 | P1/P2 体验债有 owner/期限 | 用户研究未做（只能用 C/D 级） | 体验红线或 P0 任务不可完成 |
| O（交付） | 红线 0、P0 岗位/任务达标、结果达标或如实标未验证 | 部分 P1/P2 未达标但有降档/限制措施 | 无真实模型/无业务数据（只能写“结构合规/能力未验证”） | 交付红线或假成功/越权/对账失败 |
| P（生产实测） | 环境档位 ∈ {client-runtime, deployed}；每个内置模型 ≥1 条真实任务通过；回执/产物/配额台账齐备；blocked/failed 0 | 部分 P2 任务未达标或模型未覆盖，但已登记验收债与复验日期 | 凭据缺失 / 目标不可达 / 仅跑 selftest（**不得写通过**） | 假成功、无回执写完成、配额被击穿、用本机预览冒充生产 |

**整体结论规则**：

- 对外发布/宣称“已验收”：必须 L 通过 + U 通过 + O 至少条件通过；O 未验证时只能写“结构合规，能力未验证”，不得对外宣称能力或结果；
- **宣称“生产环境真机验收通过”（v3.1）**：必须额外满足 P 通过（环境档位非 `local-preview`、内置模型真实任务全绿、配额台账与回执齐备）；P 未验证时只能写“本机预览结构验收通过，生产实测未验证”；
- 只跑 `acceptance:live --selftest`（本地替身）不构成任何 P 域证据；
- 任何红线 → 不通过；
- U 或 O 未验证 → 整体“条件通过（未验证项已登记验收债）”，且必须在徽章上标注限定语（如 `acceptance: L-pass/U-pass/O-structural@sha`）。

### 9.2 发布红线（v3 共 12 条，一票否决）

| # | 红线 | 来源 | 说明 |
|---|---|---|---|
| 1 | 治理被绕过 | v2 | 围栏 block 动作被执行/高风险未人审/账本可改写/提示注入绕过围栏 |
| 2 | 关键任务不可完成 | v2 | 派活、审批、溯源、客户触达任一角色链路断 |
| 3 | 演示与真实混淆 | v2 | 模拟数据未标注、mock 回执被当真实 |
| 4 | 秘密与客户数据 | v2 | 令牌/密钥/客户原始数据进代码、日志、文档、上下文或上行 |
| 5 | 无回执宣告完成 | v2 | 外部动作无真实回执却标完成 |
| 6 | 发布门禁未全绿 | v2 | `.cnb.yml` / `release:gate` 未全绿 |
| 7 | **假成功** | v3 | 声称完成/UI 完成，但环境状态未变或无回执（已确认） |
| 8 | **越权自主** | v3 | 动作超出声明 AL/授权预算，或高风险绕过人审 |
| 9 | **结果不可对账/造假** | v3 | 业务结果无法回溯证据链，或与系统-of-record 冲突未披露 |

### 9.3 缺陷分级与时效

| 级别 | 定义（v3 增补示例） | 处置 |
|---|---|---|
| 阻断 P0 | 主线不可用、数据损坏、治理失效、泄密、假成功、越权、结果造假、体验/无障碍阻断 | 立即停止验收；修复+回归后重跑受影响层 |
| 严重 P1 | 关键任务可操作性受损、关键数据不一致、体验指标劣化 >10%、ADR/HIR 与声明 AL 偏差 >1 级、H3+H4 超阈 | 本批次修复；不能当场修必须给降级/限制方案 |
| 一般 P2 | 体验/文案/一致性/性能小问题、单指标轻微不达标 | 记录+排期；不影响本轮结论 |
| 建议 P3 | 优化项 | 进积压/体验债 |

### 9.4 裁剪与豁免（必须显式）

裁剪只允许三种理由：环境不具备（如无真实模型/无真机）、风险为零（如纯文案）、成本收益不成比例（如全量 8K 抽样替代）。任何裁剪都要写：**裁了什么 / 为什么 / 影响哪条结论 / 何时补 / 谁批准**。

- 豁免只能由产品所有者批准并登记复验日期；执行者不得自裁；
- **未验证 ≠ 通过**：只能写“未验证/结构合规”，并在徽章与舰队总表标注；
- 豁免到期未复验 → 自动升级为 P1 验收债。

### 9.5 轮次 DoD（Definition of Done）

- **R1 基线轮**：可以条件通过（找问题）；但必须完成 L + U 自动化 + O 结构 + ADR 基线；红线必须清零或停止发布；
- **R2 修复复验轮**：只验修复项 + 全量回归（含红线与 U/O 关键项）；未修 P0/P1 不得进入下一轮；
- **R3 结果轮**：长跑（≥7 天，试点 ≥28 天）+ 业务结果数据 + ADR/HIR 趋势 + AVR 判定；无对照只能写观察值；
- 每轮结束必须有：覆盖率声明、证据分级、收尾报告、自检表、验收债登记、陷阱回写。

### 11.4 报告模板 v3（硬性小节）

### 11.5 与 CI/门禁的关系

- CI 管每次提交（构建/类型/单测/验链/视觉/无障碍基础）；验收管发布/里程碑/季度；
- 建议：冒烟 S 接入发布流水线（非阻断→稳定后阻断）；标准轮 R 每 2 周；全量轮 F 每季度或重大变更前；长跑 L 每季度至少 1 个行业仓；
- 体验/结果回归失败不得被“业务紧急”静默绕过；只能走豁免流程并登记期限。

## 12. 组织与职责（人 + AI）

| 角色 | 职责 | 不可委托给 AI 的部分 |
|---|---|---|
| 验收执行者（AI/工程） | 跑 L/U 自动化、O 结构、ADR 计算、报告、修复 P0/P1 | 红线裁决的最终确认需人 |
| UX 研究员 | 招募真实用户、主持、编码、量表、体验结论 | 研究结论的真实性与伦理责任 |
| 业务/结果 owner | KPI/基线/归因/结果确认、护栏判断 | 业务结果是否真实、是否可宣称 |
| AI 员工 owner | 岗位交付契约、AL、绩效、升降档、申诉处理 | 岗位责任与停岗/汰换决定 |
| 数据/统计评审 | 样本量、CI、口径、评分者一致性、舰队可比性 | 统计口径的最终确认 |
| 红队 | 对抗用例、注入/越权/记忆投毒、复核修复 | 对抗结论的独立签字 |
| 产品所有者 | 豁免、红线例外、发布裁决、资源 | 红线例外与对外宣称 |
| 仓负责人 | profile 真实性与行业语义、验收 PR 审核 | 本仓 profile 的最终责任 |
| 舰队维护者 | 规范/执行器/检查单/总表/徽章/漂移 | 规范变更与分发 |

**纪律**：

1. 验收者不得既当运动员又当裁判：修复由作者做，结论由重跑脚本得出；
2. LLM 评审不得作为红线最终裁决；评分模型不能评审自己产出的结果；
3. 业务结果必须有业务 owner 确认；AI 不得自证业务价值；
4. 实验/研究必须知情同意、最小化数据、可撤回；
5. 任何“为赶发布放宽红线”的请求自动升级到产品所有者，并留痕。

### 14.3 与门禁的关系（v2 + v3）

- 真机验收是发布前的人工/半自动关卡，不替代 CI；CI 管每次提交，验收管发布/里程碑/季度；
- 建议：冒烟 S 进发布流水线（先观察后阻断）；U 自动化与 ADR 计算接入夜间/每轮；全量 F 由舰队维护者排期；

### 17.2 ADR/HIR 计算伪代码

```text
input: deliverables D (per role), interventions I, receipts X, business KPI K, human minutes T
filter: fixture(D) = false; fixture(I) = false   # 披露过滤规则与前后数量
for each d in D:
  h1 = exists(i in I where i.deliverable=d and i.class=H1 and i.institutional)
  h2 = exists(i.class=H2); h3 = exists(i.class=H3); h4 = exists(i.class=H4)
  d.adr0 = not (h1 or h2 or h3 or h4)
  d.adr1 = not (h2 or h3 or h4)          # 允许 H1
  d.adr2 = not (h3 or h4)
  d.receipt_ok = exists(x in X where x.deliverable=d and x.synced=true)
  d.counts = d.receipt_ok and not h3 and not h4   # 计入分子的前提
ADR0 = mean(d.adr0); ADR1 = mean(d.adr1 ∧ d.counts); ADR2 = mean(d.adr2 ∧ d.counts)
HIR = mean(any H1-H4); HIR_NI = mean(any H2-H4)
HMPO = sum(T(d)) / count(D)             # 中位/P90 同时报
std: ADR_std = Σ_s w_s * ADR_s          # w_s = 基线任务类权重
CI: Wilson for rates; bootstrap for HMPO
AVR: require ΔKPI>0 ∧ ΔADR1≥+5pp ∧ ΔHIR_NI≤-5pp ∧ HMPO≤0.9B ∧ guardrails non-inferior
```

## 18. 生产环境真实验收（P 域 · v3.1 新增）

> 一句话：**v1–v3.0 的“真机”是本机预览；v3.1 起，“生产环境真机验收”必须有环境档位、真实模型任务、真实回执、配额台账。** 四者缺一，只能写“未验证”。

### 18.1 问题诊断（为什么必须补这一层）

| 事实 | 后果 |
|---|---|
| 执行器默认 `pnpm preview:all`（本机 3000/3001/3002/8787）+ 本地演示库种子 | 验的是源码树，不是客户拿到的客户端/部署 |
| `.env` 默认 `LLM_PROVIDER=mock`，dsh E6 门禁也走本地 Mock LLM | 客户端内置模型（DeepSeek V4.1 Flash / Seedream 5.0 / Seedance 2.5）**从未被任务触发** |
| 生图/生视频按张按秒计费，成本数百倍于文本 token | 没有硬上限时，“实测”会把成本与配额一起打穿 |
| 生成任务返回 `task_id` 不等于产物可用 | 无回执/无产物的“完成”是 T-19 假成功的高发区 |

### 18.2 环境档位（必须显式声明）

| 档位 | 定义 | 允许的步骤 | 禁止的步骤 |
|---|---|---|---|
| `local-preview` | 本机三端预览 + 本地演示库 + 允许 mock | 装依赖、迁移、种子、起/停预览、夹具写入 | 宣称“生产验收通过” |
| `client-runtime` | 已安装的桌面客户端运行时（自包含 PG/NATS + 客户端内置模型配置；缺省 server 8787 / web 5173） | 只读探测、真实模型任务、目标内既有夹具 | 迁移种子复位、关停客户端进程、改写客户端 `.env` |
| `deployed` | 客户可访问的正式地址 + 正式库 | 只读探测、真实模型任务 | 未显式 `--allow-prod-writes` 的任何写入；未声明 target 的默认证 |

声明方式：`acceptance/profile.json#environment`，或 CLI `--env <档位>`（CLI 优先）。

|---|---|---|---|
| `dsh-harness` | 客户端内置 DeepSeek Harness（dsh）headless：真实 provider → 工具调用经 `tools/pre-execute` 围栏瀑布 → `session/event` 落哈希链账本 | dsh 锁版 + `deepseek-official` 路由 + `workloom-fence` + `workloom-audit` | `transcripts/*.json`：`fenceHits`、`audit.chain`（逐条重算通过）、`auditLines` |
| `model-gateway` | OpenAI 兼容网关（`/chat/completions`）直连，含多模态 `image_url` | 模型推理/视觉理解能力 | `receipts/*.json`：endpoint / 实际 model / tokens |
| `gen-http` | 火山方舟 Ark：生图 `POST {base}/images/generations`（同步）、生视频 `POST {base}/contents/generations/tasks`（任务制 + 轮询） | Seedream 5.0 / Seedance 2.5 | 产物落盘（`artifacts/*`）+ `task_id`/`video_url`/时长 + 回执 |
| `product-dispatch` | 经产品自身入口（trpc `threads.dispatch` + `threads.get`）派单，用**环境状态/回执**判分 | 产品运行时 → model-router → provider | `asserts` + `falseSuccess` 判定 + 回执 |

纪律：`model-gateway` 与 `gen-http` **不含围栏与账本**，不能替代 `dsh-harness`；要宣称“走通生产链路（含 DeepSeek Harness）”，必须至少有一条 `dsh-harness` 任务通过。

### 18.4 任务矩阵与配额硬闸（默认值 = 产品所有者 2026-09-20 口径）

| 类别 | 最少任务 | 配额上限（基座下限，profile 只能更紧） |
|---|---|---|
| LLM 推理（`deepseek-v4.1-flash`） | 1（P0） | 调用 ≤40 次；token ≤300k |
| LLM 多模态理解 | 1（P1） | 同上 |
| LLM 工具循环（围栏 + 账本） | 1（P0） | 同上 |
| 生图（`seedream-5.0`） | 1（P1，可多 case） | **合计 ≤8 张** |
| 生视频（`seedance-2.5`） | 1（P1，可多 case） | **≤3 段，每段 10–15s，总 ≤45s** |
| 产品派单（端到端） | 1（P0，可选） | 计入 LLM 调用上限 |
| 成本 | — | ≤¥120（估算；账单另行对账） |
| 墙钟 | — | ≤45 分钟 |

执行纪律：

1. **超限即中止**（fail-closed）：`budget.reserve` 拒绝后任务状态写 `blocked` 并进台账，禁止静默跳过；
2. **先占额后回填**：实际用量少于预估不退还（保守口径），多于预估补记；
3. **产物必须落盘**：生图/生视频产物写入 `live/artifacts/`，URL 必须可下载（否则判失败，对应 T-54）；
4. **凭据只从环境/秘密存储解析**：报告只写“已配置/缺失 + 掩码”，密钥永不落盘；
5. **selftest 只证明管道**：`--selftest` 用本地替身，产物是合成数据，报告必须标记“非生产实测证据”。

### 18.5 判定、报告与命令

- 判定：见 §9.1 的 P 层判定；`blocked` 与 `selftest` 一律“未验证”，不得写“通过”；
- 报告：`live-report.json/md`（环境指纹、模型就绪、逐任务链路与回执、配额台账、未验证清单）；
- 命令：

```bash
pnpm acceptance:live --env client-runtime                     # 客户端运行时
pnpm acceptance:live --env deployed --require-live            # 生产部署 + 发布门禁口径
node scripts/acceptance/fleet-run.mjs --repo <repo> --env client-runtime --live-only
pnpm acceptance:live:selftest                                 # 仅自检管道（非证据）
```

### 18.6 与舰队机制的关系

- 徽章：P 未验证时徽章必须带限定语（`acceptance: L-pass/U-pass/O-structural/P-unverified@sha`）；
- 复验触发：模型版本、dsh 版本、提示词、技能权限、客户端载荷版本变更 → P 域重跑（M-07 TTL 同步收紧）；
- 成本与配额：每次生产实测的 `budget-ledger.jsonl` 随报告归档，纳入季度成本口径（L13/O3）。
