# 语音与数字员工交付契约

> 适用：WorkLoom 基座及全部行业 Bundle。目标是让语音、数字人和 3D 职场成为产品能力，而不是机器相关的演示效果。

## 1. 当前正式链路

- 所有播报只能进入 `VoiceEngine` 单消费者队列；除熔断外不得打断正在播放的句子。
- 同一角色第一次选中系统 voice 后必须锁定，后续段落不得重新猜测；voice 列表未就绪时锁定系统默认声，宁可全程一致，也不能中途变声。
- 角色配置明确区分男女声；织伴固定为柔和中文女声，优先 `Flo / Tingting / Xiaoxiao / Xiaoyi / Meijia / Sinji`，音高只做轻微修饰。
- TTS 开始时环境声自动 duck 到 0，结束后平滑恢复；首次安装默认“仅反馈+仪式”，不默认播放连续白噪。
- 欢迎介绍控制在四个短段内：问候、系统价值、权限原则、团队引出。字幕与语音使用同一文本，禁止另起长文案。

## 2. 神经 TTS 选型

系统 TTS 作为零下载兜底保留；高品质声音以可选“本地神经语音包”提供，不能把数 GB 模型强塞进每个基础安装包。

首选评估 `QwenAudio/CosyVoice`：Apache-2.0，中文与多语言、流式输出、情绪/语速/音量指令均由官方实现。目标接入形态是独立本机 sidecar，Electron 通过受限 IPC 请求 PCM 流，前端 `AudioContext + AnalyserNode` 直接驱动口型。

备选：

- `fishaudio/fish-speech`：表达力和多角色能力强，需在商业分发前单独复核模型权重许可与运行资源。
- `hexgrad/Kokoro-82M`：模型小、Apache-2.0 权重，适合轻量包，但中文情绪控制不是当前首选。
- `appautomaton/mlx-speech`：Apple Silicon 本机推理友好，可做 macOS 实验后端；不是 Windows 的统一交付方案。

神经语音包进入正式发布前必须实测：M1/M3 首包延迟、实时率、峰值内存、中文数字/英文缩写读法、离线可用、许可证与安装包增量。未过门禁不得替换稳定兜底。

## 3. 数字员工视觉

- 正式职场和团队仪式禁止使用骑士、法师、武器、盔甲等与办公语义无关的素材。
- 正式人物使用现代商务装统一骨架；岗位通过服装色、发型、胸牌和动作区分。
- 默认名牌只显示岗位/角色名；用户设置别名后只显示别名。系统生成的人名不得出现在 3D 职场、团队仪式或语音汇报中。
- 同一目的地的角色必须使用确定性槽位布局，禁止随机抖动造成角色/名牌相互覆盖。
- 团队舞台的 `ready=true` 必须表示所有角色已经完成首帧入场，不得只因容器挂载就报告就绪。

## 4. 发布门禁

每次发布必须在打包后的可执行程序上验证：

1. 欢迎文案总长度与每段数量上限；
2. 同一角色连续多段使用同一 voice，普通播报最大并发为 1；
3. TTS 播放期间环境总线增益为 0；
4. 角色名牌 DOM 中不存在系统默认人名，且团队人数与 Bundle 编制一致；
5. 欢迎页、团队仪式、职场和舞台四张截图通过非黑屏、人物包围盒、标签密度检查；
6. 默认与安全渲染模式分别验收。
